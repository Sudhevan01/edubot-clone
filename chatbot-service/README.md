# EduCrop Chatbot Backend Service

FastAPI backend service for the EduCrop landing page visitor chatbot. Answers visitor queries using Gemini LLM strictly based on content in `knowledge/knowledge.md`.

## Setup & Running

### 1. Install Dependencies
```bash
pip install -r requirements.txt
```

### 2. Environment Variables
Ensure `.env` exists in the repository root directory:
```env
GEMINI_API_KEY=your_gemini_api_key_here
```
All other configuration options (model, origins, rate limits) have sensible defaults in `app/config.py`.

### 3. Run the Server
From `chatbot-service/`:
```bash
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```
- Interactive Swagger UI: `http://127.0.0.1:8000/docs`
- Health check: `http://127.0.0.1:8000/api/health`

## API Contract

### Health Check
`GET /api/health`
**Response (200 OK)**:
```json
{ "status": "ok" }
```

### Chat Endpoint
`POST /api/chat`

**Request Body**:
```json
{
  "session_id": "123e4567-e89b-12d3-a456-426614174000",
  "message": "What modules does EduCrop provide?",
  "input_mode": "text"
}
```
* `input_mode` (optional, string): Input mode indicator (`"text"` or `"voice"`). Defaults to `"text"`.

#### Frontend Developer Voice Input Guidelines
When integrating voice input with the Web Speech API:
1. **Speech Recognition Config**: Use Web Speech API (`webkitSpeechRecognition` / `SpeechRecognition`) with `lang` set to `"en-IN"`.
2. **User Editing**: Populate the transcribed text directly into the chat input text area/box so the user can review and edit it before clicking send. Do **not** auto-send immediately upon speech end.
3. **Set Input Mode**: Set `input_mode: "voice"` when sending a message transcribed from the microphone; set `input_mode: "text"` (or omit) when typed.
4. **Browser Support**: Hide or disable the microphone button if the user's browser does not support `SpeechRecognition`.
5. **HTTPS Requirement**: Secure HTTPS connection is required in production environments to access the microphone device via browser Web APIs.

#### Response Fields & Frontend Developer Notes
* `answer` (string): Main bot response text.
* `page` (object or null): Backward-compatible referenced landing page route details (`key`, `label`, `url`).
* `answer_type` (string): Response classification: `"answered"`, `"not_found"`, or `"off_topic"`.
* `actions` (array of objects): Action buttons/links generated by the backend:
  * `{ "type": "navigate", "label": "View Contact", "url": "/contact" }`
  * `{ "type": "email", "label": "Email the school", "value": "Educropblr@gmail.com", "subject": "Question from website" }`
* `suggestions` (array of strings): Recommended follow-up query chips chosen from configuration.

##### Frontend Developer UI Rendering Notes:
1. **Navigate Actions**: Render `type: "navigate"` actions as primary buttons using your frontend router to navigate smoothly to `action.url`.
2. **Email Actions**: Render `type: "email"` actions as links or buttons opening a mail client: `mailto:<action.value>?subject=${encodeURIComponent(action.subject)}`.
3. **Suggestions**: Render `suggestions` array items as clickable chip components. When clicked, populate and auto-send the suggestion text as the next chat message.

## Updating Knowledge Base

When landing page site content changes:
1. Update `knowledge/knowledge.md` with plain text content for each page section (`# Home (/)`, `# Product (/product)`, etc.).
2. If new pages are added or URLs change, update `knowledge/pages.json` mapping each page key to its label and relative URL path.
3. Restart the FastAPI application (knowledge base is loaded into memory at startup).
